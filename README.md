# Ваш фермер — интернет-магазин (Новокузнецк)

Интернет-магазин фермерских продуктов (мясо, ягоды, молочные продукты и т.д.)
на чистом PHP + MySQL, с оплатой через Сбербанк Эквайринг и админ-панелью
для управления заказами и каталогом товаров.

## Требования к хостингу

- PHP 8.0+ с расширениями: `pdo_mysql`, `curl`, `mbstring`, `fileinfo`
- MySQL / MariaDB 5.7+/10.3+
- Apache с поддержкой `.htaccess` (`mod_rewrite` не обязателен, используется `mod_authz_core`/`mod_access_compat` для `Require all denied`)

## Установка

1. **База данных.** Создайте базу данных и импортируйте `sql/schema.sql`:
   ```
   mysql -u root -p -e "CREATE DATABASE vashfermer CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;"
   mysql -u root -p vashfermer < sql/schema.sql
   ```
   Схема сразу создаёт демонстрационные категории/товары, настройки сайта
   и администратора: **логин `admin`, пароль `admin123`**.
   Обязательно смените пароль в разделе «Настройки сайта» после первого входа.

   Если сайт был установлен ранее (до появления архива заказов), примените
   миграцию `sql/migrate_archive.sql` к существующей базе данных.

2. **Конфигурация.** Откройте `config/config.php` и укажите:
   - параметры подключения к БД (`DB_HOST`, `DB_NAME`, `DB_USER`, `DB_PASS`);
   - `SITE_URL` — адрес сайта без слэша на конце;
   - данные Сбербанк Эквайринга (`SBER_USERNAME`/`SBER_PASSWORD` или `SBER_TOKEN`),
     которые выдаются банком при подключении интернет-эквайринга;
   - `SBER_MODE` — `test` для тестового стенда, `prod` — для реальных платежей.

3. **Загрузите файлы** на хостинг так, чтобы корень сайта (`index.php`, `admin/`,
   `assets/`, ...) находился в публичной директории (`public_html`, `www` и т.п.).

4. **Права на папку загрузок.** Убедитесь, что веб-сервер может писать в
   `uploads/products/` и `uploads/categories/` (права 755/775).

5. Откройте `https://ваш-домен/admin/login.php`, войдите под `admin`/`admin123`
   и смените пароль в разделе «Настройки сайта».

## Структура проекта

```
config/           конфигурация и подключение к БД
includes/         общие компоненты (шапка, подвал, функции, корзина)
assets/           CSS, JS, изображения-заглушки
uploads/          загруженные фото товаров и категорий (создаются автоматически)
payment/          интеграция с Сбербанк Эквайрингом
admin/            панель администратора
sql/schema.sql    схема БД и demo-данные
sql/migrate_archive.sql   миграция архива заказов для ранее установленных сайтов

index.php         главная страница
catalog.php       каталог / категория
product.php       страница товара
cart.php, cart_actions.php   корзина (AJAX)
checkout.php      оформление заказа
order_success.php, order_fail.php   результат оплаты
about.php         страница «О нас»
contacts.php      контакты + карта (Яндекс.Карты)
```

## Оплата через Сбербанк

Используется REST API «Сбербанк Эквайринг»
(`https://securepayments.sberbank.ru/payment/rest/` для продакшена,
`https://3dsec.sberbank.ru/payment/rest/` для тестового стенда).

- При оформлении заказа с оплатой картой создаётся заказ в БД (`payment_status = pending`),
  затем вызывается `register.do` и покупатель перенаправляется на страницу оплаты банка.
- После оплаты пользователь возвращается на `order_success.php` или `order_fail.php` —
  на этих страницах статус **дополнительно перепроверяется на сервере** через
  `getOrderStatusExtended.do`, чтобы не доверять параметрам в адресной строке.
- Дополнительно `payment/callback.php` можно указать в личном кабинете эквайринга
  как URL уведомлений (notificationUrl) для надёжного серверного оповещения об оплате.

Реквизиты `SBER_USERNAME`/`SBER_PASSWORD` (или `SBER_TOKEN`) для подключения
выдаёт банк при заключении договора на интернет-эквайринг.

## Админ-панель

`/admin/` — вход по логину/паролю (таблица `admin_users`).

- **Дашборд** — сводная статистика по заказам.
- **Заказы** — список (только активные), фильтр по статусу/поиску, просмотр состава
  заказа, изменение статуса заказа и статуса оплаты.
- **Архив заказов** — заказы со статусом «Выполнен» автоматически переносятся сюда
  и не засоряют список активных заказов; из карточки заказа их можно вернуть обратно.
- **Товары / Категории** — добавление, редактирование, удаление, загрузка фото,
  управление наличием и видимостью на сайте.
- **Настройки сайта** — телефон, адрес, режим работы, координаты карты, ссылки
  на соцсети, стоимость доставки, текст страницы «О нас», смена пароля администратора.

## Безопасность

- Все запросы к БД выполняются через подготовленные выражения (PDO, без конкатенации SQL).
- Пароли администраторов хранятся как bcrypt-хэши (`password_hash`).
- Формы защищены CSRF-токенами.
- Папка `uploads/` запрещает выполнение скриптов (`.htaccess`), загружаются только
  изображения (JPG/PNG/WEBP) с проверкой MIME-типа и ограничением размера.
- Прямой доступ к `config/`, `includes/`, `admin/includes/` и внутренним файлам
  `payment/` закрыт через `.htaccess`.
